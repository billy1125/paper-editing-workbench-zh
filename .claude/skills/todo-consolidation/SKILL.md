# 待辦彙整（Todo Consolidation）

目的：各章的待補事項、工作筆記、文內標記與 ⚠️ 觀察散在不同檔案，容易重複或漏掉。這個 skill 把它們彙整成一份 `todo.md`，作為作者需要處理的唯一清單。`progress.md` 只作歷程紀錄，不承擔待辦追蹤。

## 何時用

- 第一次為一篇論文建立 `todo.md`。
- 編修一段時間後更新：新的 ⚠️、新的 TODO、已處理的事項要結案。
- `editing-assistant` 回報 `todo.md` 過時（`revisions/` 有晚於彙整日期的紀錄）。

## 開始前

1. 確認作用中論文 `working-papers/<title>/`。
2. 依該篇 `Basic Information.md` 的 `chapters` 取得章節檔清單，不自行增減，不寫死檔名。`chapters` 未設定時先請作者設定。
3. 以章節檔的 **live 內容**為準。
4. 讀現有的 `todo.md`（若存在），記下既有編號與最大的 U、R 編號。

## 來源範圍

| 來源 | 內容 |
|---|---|
| 各章章末 | 「待補事項」「工作筆記」「編修紀錄」等不納入投稿正文的節 |
| 文內標記 | `[TODO…]`、`[No Reference]`、`[Need Reference]`、`[待補文獻]`、`[待確認…]` |
| `revisions/` | 各筆「備註」中的「⚠️ 觀察」 |
| 不納入 | `progress.md`（只作歷程紀錄）；`Manuscript.md`；`drafts/`；`papers/` |

`[Verified]` 是已完成的標記，不列為待辦。

## 步驟

1. **收集**：逐章抽出上述來源，記下檔名、行號、所在節號；`revisions/` 的 ⚠️ 記下紀錄檔名。
2. **合併重複**：同一事項出現在多處（章末待補與文內標記、跨章同一筆文獻、多筆 revisions 沿用的同一個 ⚠️）合併為一項，「來源」欄列出合併前的所有出處。
3. **核對正文**：對每一項，到章節檔 live 內容確認是否已處理。
   - 有依據（正文已改、標記已移除、`revisions/` 有對應紀錄）→ 歸「已解決」，寫明處理情形與依據。
   - 判斷不了 → 留在未解決，不推定已處理。
4. **分類**：

   | 代碼 | 分類 |
   |---|---|
   | A | 引用查證（原文缺漏或尚未查證） |
   | B | 參考文獻書目 |
   | C | 資料與數值 |
   | D | 理論依據待補文獻 |
   | E | 待作者決定（寫法與定位） |
   | F | 投稿前處理 |
   | G | 工作筆記整理 |
   | H | ⚠️ 觀察（只收不屬於 A–G 的 ⚠️；能歸入 A–G 的放進該類，來源欄註明出自哪筆 revisions） |

5. **寫項目**：每項包含下列欄位。

   | 欄位 | 必填 | 說明 |
   |---|---|---|
   | 編號＋標題 | 是 | `U-xx`（未解決）、`R-xx`（已解決），兩位數 |
   | 位置 | 是 | 檔名＋行號或節號 |
   | 來源 | 是 | 合併前的出處 |
   | 現況 | 否 | 目前檔案裡的實際狀態 |
   | 建議作法 | 是 | 能用既有 skill 處理的寫出 skill 名；需作者決定的列選項 (a)(b)，不替作者選 |

   已解決項目只寫「原事項」與「處理情形」。

6. **寫檔頭**：彙整日期、來源範圍、不納入的範圍、「行號以彙整日期的章節檔為準」、編號規則。
7. **寫入 `todo.md`**，不在 `revisions/` 留底。
8. **記歷程**：在該篇 `progress.md` 表格前的說明區塊末尾加一行，格式如下：

   ```
   > YYYY-MM-DD 更新 `todo.md`：未解決 N 項、已解決 M 項；新增 U-xx、U-yy；結案 U-zz（→ R-ww）。
   ```

   第一次建立時寫「新增 `todo.md` 彙整 <範圍>：未解決 N 項、已解決 M 項」。

## 增量更新規則

`todo.md` 已存在時：

- 既有編號不重排，其他檔案與對話引用的 U-xx 才不會失效。
- 已處理的 U 項移到「已解決」，取得下一個 R 編號，並註明原 U 編號。
- 新事項取得下一個 U 編號，放進對應分類。
- 所有項目的「位置」依當下章節檔重算行號；檔頭彙整日期與來源範圍更新。
- 既有 `todo.md` 的來源範圍與本 skill 不同時（例如舊版沒收 `revisions/` 的 ⚠️），依本 skill 補收，並在檔頭寫明。

## 與其他 skill 的分工

| 情況 | 交給 |
|---|---|
| `[No Reference]` 補上原文、需重查 | `citation-source-verification` |
| 書目缺漏或待核對 | `citation-reference-management` |
| 用詞統一、全文一致性 | `final-consistency-sweep` |
| 跨章論證或模型規格不一致 | `argument-review` |
| 段落改寫 | `passage-revision` |

## 界線

- 只寫該篇 `todo.md` 與 `progress.md` 的一行歷程。
- 不改章節檔、不刪或改文內標記、不刪章末待補事項。章節檔內 TODO 的刪改依使用者指示另行處理，並照 CLAUDE.md §5 在 `revisions/` 留底。
- 不判斷研究邏輯或主張對錯；「待作者決定」類只列選項。

## `todo.md` 格式

```markdown
# 待辦彙整（<範圍>）

> 彙整日期：YYYY-MM-DD。來源：各章節檔的「待補事項」「工作筆記」「編修紀錄」、文內標記（`[TODO]`、`[No Reference]`、`[Need Reference]`、`[待補文獻]`、`[待確認]`）與 `revisions/` 的 ⚠️ 觀察；`progress.md` 不納入。
> 重複項目已合併，「來源」欄列出合併前的出處。行號以彙整日期的章節檔為準。
> 編號：U = 未解決，R = 已解決。既有編號不重排，新項目接續編號。

---

## 未解決

### A. 引用查證（原文缺漏或尚未查證）

**U-01　<標題>**
- 位置：`<章節檔>` 第 N 行
- 來源：<出處>
- 現況：<選填>
- 建議作法：<skill 或選項 (a)(b)>

### B. 參考文獻書目
…
### H. ⚠️ 觀察
…

---

## 已解決

**R-01　<標題>**
- 原事項：<原 U 編號與內容>
- 處理情形：<依據>
```

## 回報

只回報 `todo.md` 路徑、未解決與已解決的項數、本次新增與結案的編號。
